# Word (.docx) 详细设计说明书 JSON 规范与模块模板

`scripts/build_from_spec.py` 接收一个或多个有序 JSON 文件合并生成正式 `.docx` 文档。

---

## 1. 顶层 JSON 结构

```json
{
  "docTitle": "<产品/系统> 软件开发详细设计说明书（<专题/模块>）",
  "headerTitle": "<产品/系统> 软件开发详细设计说明书 V1.0",
  "creator": "<开发团队>",
  "blocks": [
    { "type": "doc_title", "text": "..." },
    { "type": "table", "headers": ["项目", "内容"], "rows": [...], "colWidths": [2800, 6843] },
    { "type": "toc" },
    { "type": "heading", "level": 1, "text": "1 引言", "pageBreak": true, "estPage": 3, "center": true }
  ]
}
```

> 多模块文档可拆分为 `spec_part1.json`、`spec_part2.json` ...，通过 `--spec spec_part1.json spec_part2.json` 按序传入（仅首文件需包含 `docTitle`/`headerTitle`）。

---

## 2. 支持的 Block 类型

| `type` | 必填字段 | 可选字段 | 说明 |
| :--- | :--- | :--- | :--- |
| `doc_title` | `text` | — | 封面居中大标题（不进入目录） |
| `toc` | — | — | 自动目录占位，插入后由 `TocEntries` 自动填充 |
| `blank` | — | `size` (默认8) | 小间距空行 |
| `heading` | `level` (1..5), `text` | `pageBreak` (bool), `estPage` (int), `center` (bool) | 1~3 级自动记入 TOC 书签（均须显式填单调非降 `estPage`，防目录回退显示 `1`）；内置 `<w:keepNext>` |
| `para` | `text` | `boldPrefix`, `spaceAfter` | 正文左对齐段落（`3.x.3.k Method(...)` 且 `len>32` 自动拆出深蓝加粗标题行） |
| `bullet` | `text` | `boldPrefix` | 项目符号列表项 |
| `steps` | `items` (string[]) | — | 自动编号步骤（`1. ... 2. ...`） |
| `code` | `lines` (string[]) | — | `Consolas` 左蓝竖线浅灰底代码块（仅用于报文/配置示例，**不贴实现源码**） |
| `table` | `headers`, `rows` | `colWidths` (总和9643), `centerCols` (int[]) | `#2E74B5` 蓝底白字表头；内边距充裕，内置首行 `keepNext` 与 `<=3` 行短表防拆分 |
| `api_card` | `method`, `endpoint`, `summary` | `tag`, `trigger`, `request`, `fields` (`[{name,desc}]`), `display`, `fallback` | **外部接口/MQTT/UDP 专用信息卡**：突出方法与路径，分点展示关键字段中文语义及异常兜底，不拥挤 |
| `image` | `file`, `caption` | `maxWidthEmu` (默认5852160) | 居中插入高清图及加粗图题 |

## 3. 文档结构模式与章节骨架

### 3A. 核心模块可迁移版（`--mode module`：便于往主模板《3 模块详细设计》移植合并）

> 当主工程设计文档已具备全局第 1、2 章时使用本模式：不生成冗余封面页/目录页及第 1、2 章，聚焦交付可整体移植的 **《3 模块详细设计》**；一个大功能域收口为 `3.1 <模块名称>`（若单文档确含少数并列大功能页面可列 `3.1`、`3.2`...），便于人工复制或交由迁移工具按需顺延编号合入。

- **文档头提示**：`doc_title`（模块设计专题名） + 1 句简明移植指引说明
- **`3 模块详细设计`**（`level: 1`）：
  - `3.0 模块清单`（简表列出本专题功能与职责）
  - `3.1 <大模块名称>`（逐节对应主模板标准小节）：
    - `3.1.1 方案概述`（功能职责 + `3.1.1.1 用户界面设计` + `3.1.1.2 功能模块设计`：中文工程语言配全景/环节流程图与时序图，**异常与网络处理直接画进主流程**）
    - `3.1.2 三方依赖设计`（中文职责表 + 降级策略，不堆砌源码符号）
    - `3.1.3 实现接口设计`（**按职责分组的 UML 类图** + 精简核心类/对外能力职责描述，不铺私有变量与内部权重常量）
    - `3.1.4 功能规格设计`（`3.1.4.1 接口契约` 使用 `api_card` 清晰分点列出方法/路径、入参、核心字段、展示消费与网络异常兜底；`3.1.4.2` 数据校验；`3.1.4.3` 状态流转与异常表；`3.1.4.4` 关键配置与联调端点汇总表——若含具体 IP 集中放于此表）
    - `3.1.5 DFX 分析与设计`（可靠性与安全，精炼不跑偏）
    - `3.1.6 使用举例`（1~2 个覆盖“正常主闭环 + 网络/异常自愈”的可读场景）

### 3B. 完整独立说明书版（`--mode full`：对应 `TPL-SDD-V2.0` 全章版）

> 正式成稿**必须剔除**模板中的 `0 使用说明`、`填写约定`、`填写要求` 及所有 `【】` 占位；需独立成册移交时保留第 1~3 章及末尾 `附录 A`。

- **封面**：`doc_title` + 7 行文档信息表（文档编号、项目名称、适用对象、设计输入、主要用途、版本/密级、编制/评审/批准）+ `toc`
- **1 引言**：`1.1 ~ 1.6`
- **2 设计概览**：`2.1 ~ 2.3`
- **3 模块详细设计**：`3.0 模块清单` + 各大模块 `3.x`（`3.x.1 ~ 3.x.6` 骨架同 3A）
- **附录 A（完整独立版有外部接口/MQTT/联调端点时必需）**：`附录 A 外部接口契约、MQTT 主题与联调端点一览`（`A.1` 外部接口、`A.2` MQTT 主题、`A.3` 联调 IP/端口对照）

## 4. 正式 `.docx` 可读性与交付质量门禁规则

1. **禁止“代码符号轰炸”与折行乱象**：正文、流程图与常规表格优先使用通俗清晰的中文表达；禁止将私有变量、内部 UI 布局权重（如 `HOME_LEFT_ROW_WEIGHT`）、历史废弃分支填入普通表格与叙述段落；核心类关系由 UML 类图呈现，接口字段由 `api_card` 重点突出展示。
2. **聚焦主功能与网络/异常闭环**：所有请求与业务链均需明确说明正常流程及超时、断连、401 失效、空/越界数据的兜底行为，不写无关扩展或跑题枝节。
3. **禁止 `.md` 外部基线引用**：`.docx` 封面“设计输入”、正文均不得出现内部 `*.md` 文件名；已有 `.md` 转 `.docx` 时须将核心规则与字段完整内化。
4. **正文去 IP 化**：正文叙述、流程图与一般表格不写具体环境 IP，统一放在 `附录 A` 或专门的`联调端点配置表`中。
5. **排版与表头防双绘**：禁止使用 `both` 两端对齐；表格首行必须通过 `docx_builder.py` 写入 `<w:keepNext w:val="1"/>`，`<= 3` 行短表整体不跨页拆散。
6. **禁止列举文字堆砌**：任何 `1/2/3`、`①/②/③` 或 `1）/2）` 多点列举**严禁**写进同一个分号隔开的长句里！正文中请拆为 `"steps"` 或多条 `"bullet"`；`api_card` 的 `"trigger"` / `"request"` / `"display"` / `"fallback"` 支持传入字符串数组（`["1. ...", "2. ..."]`）自动渲染为一行为一条的清晰子列表；表格单元格中可用 `\n` 或字符串数组自动分段落呈现。`--strict-delivery` 会拦截未分行的 `①...②`、`1）...2）` 堆砌。
7. **`3.x.3` 代码设计重架构、枚举与类契约**：`3.x.1~3.x.2` 侧重业务流程与正常/异常闭环；`3.x.3 实现接口设计` 须侧重真实代码架构——给出按职责分组的 UML 类图（含 `<<enum>>` / `<<Model>>` / `<<Service>>` 角色）、**核心枚举（Enum）与状态模型定义表**，以及骨干类核心对外方法的完整签名、入参、返回值与协作者职责（仍不贴函数内部实现体）。
8. **共性基础能力收敛 `3.99` 与多模块装配（`merge_sdd.py`）**：多个业务模块共享的登录续期、公共 HTTP 重试与切页取消、全局资源配额池、跨模块共享面板统一写进 `3.99 公共基础能力设计`（`3.99.1`, `3.99.2`...），`3.1 ~ 3.n` 仅声明复用引用与差异边界，不重复抄写。多模块合并及已有主 `.docx` 插入请调用 `merge_sdd.py inspect | assemble | inject`，自动重排 `3.x` / `图 3-k` 序号、对 `3.99` 去重并刷新可点击目录书签。
